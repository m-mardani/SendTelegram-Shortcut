# hold2tg

فایل‌ها یا متنی را که انتخاب کرده‌اید، با **نگه‌داشتن `Ctrl + Shift + S` به مدت ۵ ثانیه** به کانال تلگرام‌تان می‌فرستد. برای اوبونتو (GNOME)، هم روی X11 و هم Wayland.

- در پنجرهٔ **Files (Nautilus)** فایل یا پوشه انتخاب کرده‌اید → همان‌ها ارسال می‌شوند (پوشه به‌صورت zip).
- در هر برنامهٔ دیگری متن را **هایلایت** کرده‌اید → همان متن ارسال می‌شود. لازم نیست Ctrl+C بزنید.
- کلید و مدت نگه‌داشتن قابل تغییر است.
- یک گزینهٔ «ارسال به تلگرام» هم به منوی راست‌کلیک Files اضافه می‌شود.

## نصب

### ۱. ربات و کانال

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام `/newbot` بدهید و **توکن** را بگیرید.
2. ربات را به‌عنوان **ادمین** به کانال اضافه کنید (دسترسی «Post Messages» کافی است).

### ۲. نصب برنامه

```bash
unzip hold2tg.zip && cd hold2tg
./install.sh
```

اسکریپت با کاربر عادی اجرا می‌شود و فقط برای دو کار `sudo` می‌خواهد: نصب بسته‌های apt و اجازهٔ خواندن رویدادهای صفحه‌کلید.

### ۳. تنظیم

```bash
nano ~/.config/hold2tg/config.ini
```

```ini
[telegram]
bot_token = 123456789:AAE...
chat_id = @my_channel
```

- کانال عمومی: `chat_id = @username`
- کانال خصوصی: یک پیام در کانال بگذارید، بعد `hold2tg chats` را اجرا کنید و شناسهٔ عددی (`-100...`) را بردارید.
- اگر تلگرام روی شبکهٔ شما مستقیم باز نمی‌شود، `proxy` را تنظیم کنید؛ مثلاً ورودی محلی v2ray/xray:
  `proxy = socks5h://127.0.0.1:10808`

بعد:

```bash
hold2tg test                        # یک پیام آزمایشی به کانال می‌فرستد
hold2tg doctor                      # همه‌چیز را بررسی می‌کند
systemctl --user restart hold2tg    # بعد از هر تغییر در تنظیمات
```

## استفاده

| کاری که می‌کنید | چیزی که ارسال می‌شود |
|---|---|
| در Files چند فایل/پوشه انتخاب می‌کنید و کلیدها را ۵ ثانیه نگه می‌دارید | همان فایل‌ها (هر کدام یک پیام؛ پوشه‌ها zip) |
| در مرورگر، ترمینال، ویرایشگر و… متنی را هایلایت می‌کنید و کلیدها را نگه می‌دارید | همان متن (متن طولانی به چند پیام تقسیم می‌شود) |

بعد از ۵ ثانیه یک اعلان «در حال ارسال…» می‌آید و می‌توانید کلیدها را رها کنید؛ نتیجه هم با اعلان گزارش می‌شود. اگر زودتر رها کنید هیچ چیزی ارسال نمی‌شود.

قاعدهٔ انتخاب بین فایل و متن: **اگر پنجرهٔ Files فعال باشد فایل‌ها، در غیر این صورت متن هایلایت‌شده.** فایل‌هایی که در یک پنجرهٔ غیرفعال انتخاب مانده‌اند هیچ‌وقت ارسال نمی‌شوند.

دستورهای دیگر:

```bash
hold2tg send-selection          # همین حالا، بدون نگه‌داشتن کلید
hold2tg send-text "سلام"        # یا: echo متن | hold2tg send-text
hold2tg send-files a.pdf dir/
```

## تنظیمات

همه در `~/.config/hold2tg/config.ini` (توضیح هر گزینه داخل خود فایل هست):

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `[hotkey] keys` | `ctrl+shift+s` | مثلاً `ctrl+alt+t` یا `super+f9` |
| `[hotkey] hold_seconds` | `5` | مدت نگه‌داشتن |
| `[telegram] proxy` | خالی | `socks5h://…` یا `http://…` |
| `[telegram] silent` | `false` | ارسال بدون صدای اعلان برای اعضا |
| `[behavior] max_file_mb` | `50` | سقف Bot API تلگرام ۵۰ مگابایت است |
| `[behavior] max_files` | `20` | اگر بیشتر انتخاب شده باشد چیزی ارسال نمی‌شود |
| `[behavior] zip_folders` | `true` | پوشه به‌صورت zip |
| `[behavior] language` | `fa` | زبان اعلان‌ها: `fa` یا `en` |

## چیزهایی که باید بدانید

- **تداخل کلید:** برنامه فقط کلیدها را «می‌شنود» و جلوی رسیدن‌شان به برنامهٔ فعال را نمی‌گیرد. `Ctrl+Shift+S` در خیلی از برنامه‌ها «Save As» است (LibreOffice، VS Code، gedit) و در فایرفاکس ابزار اسکرین‌شات؛ یعنی هنگام نگه‌داشتن، آن پنجره هم باز می‌شود. متن در همان لحظهٔ فشردن کلید برداشته می‌شود، پس ارسال درست انجام می‌شود، ولی اگر آزاردهنده بود `keys` را به ترکیبی بدون تداخل عوض کنید (مثلاً `ctrl+alt+t` یا `super+f9`).
- **دسترسی به صفحه‌کلید:** برای تشخیص «نگه‌داشتن» روی Wayland راهی جز خواندن `/dev/input` نیست. نصب، با یک قانون udev به کاربری که پشت سیستم نشسته اجازهٔ خواندن رویدادهای صفحه‌کلید می‌دهد. نتیجه‌اش این است که هر برنامه‌ای که با کاربر شما اجرا شود هم می‌تواند کلیدها را بخواند (مثل عضویت در گروه `input`). اگر این را نمی‌خواهید نصب نکنید و به‌جایش `hold2tg send-selection` را در Settings → Keyboard → Custom Shortcuts به یک میان‌بر معمولی وصل کنید (بدون قابلیت نگه‌داشتن).
- **جانمایی صفحه‌کلید مهم نیست:** کلید فیزیکی S ملاک است؛ با کیبورد فارسی هم کار می‌کند.
- **فقط Files (Nautilus):** انتخاب فایل در مدیر فایل‌های دیگر یا آیکون‌های روی دسکتاپ خوانده نمی‌شود.
- **فایل‌ها به‌صورت Document** فرستاده می‌شوند (بدون فشرده‌سازی عکس). فایل خالی و فایل بزرگ‌تر از سقف رد می‌شود و در اعلان گفته می‌شود.
- توکن ربات در `config.ini` با دسترسی `600` می‌ماند و در لاگ‌ها نوشته نمی‌شود. متن ارسالی هم لاگ نمی‌شود.

## عیب‌یابی

```bash
hold2tg doctor                      # اول این
journalctl --user -u hold2tg -f     # لاگ زنده
systemctl --user status hold2tg
```

| مشکل | راه‌حل |
|---|---|
| `no readable keyboard` | یک بار خارج و وارد شوید. اگر درست نشد: `./install.sh --input-group` و دوباره ورود. |
| فایل‌ها ارسال نمی‌شوند ولی متن می‌شود | `nautilus -q` و دوباره Files را باز کنید؛ بستهٔ `python3-nautilus` باید نصب باشد. |
| `chat not found` | ربات ادمین کانال نیست یا `chat_id` اشتباه است. |
| خطای شبکه / timeout | `proxy` را در تنظیمات بگذارید. |
| متن خالی خوانده می‌شود (Wayland) | `text_backend = wl-paste` را امتحان کنید. |

## حذف

```bash
./uninstall.sh            # تنظیمات می‌ماند
./uninstall.sh --purge    # همراه با تنظیمات
```

## ساختار و تست

```
hold2tg/hotkey.py      منطق تشخیص نگه‌داشتن (بدون وابستگی)
hold2tg/listener.py    سرویس پس‌زمینه؛ خواندن صفحه‌کلید با evdev
hold2tg/selection.py   خواندن متن هایلایت‌شده و فایل‌های انتخاب‌شده
hold2tg/telegram.py    کلاینت Bot API
hold2tg/sender.py      ارسال متن/فایل، zip پوشه، سقف‌ها
nautilus/              افزونهٔ Files
systemd/  udev/        سرویس کاربر و قانون دسترسی
```

```bash
python3 -m unittest discover -s tests -t .
```

وضعیت تست: منطق نگه‌داشتن، کلاینت تلگرام (با یک سرور شبیه‌ساز)، ارسال فایل/پوشه و حلقهٔ سرویس با تست خودکار پوشش داده شده‌اند. افزونهٔ Files و خواندن متن روی Nautilus 46 و mutter 46 (نسخه‌های اوبونتو ۲۴.۰۴)، هم X11 و هم Wayland، با برنامه‌های واقعی امتحان شده است؛ روی نسخه‌های قدیمی‌تر (مثل اوبونتو ۲۲.۰۴ با Nautilus 42) امتحان نشده. خواندن صفحه‌کلید واقعی از `/dev/input` و ارسال به تلگرام واقعی در محیط ساخت قابل تست نبود؛ بعد از نصب با `hold2tg doctor` و `hold2tg test` بررسی‌اش کنید.
